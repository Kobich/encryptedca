# Формат QR-кодов для импорта профиля

Профиль — это клиентский `.p12` и сертификат CA. Они передаются набором QR-кодов. Приложение читает их в любом порядке и по несколько штук за кадр, а также с картинки: скриншота или фото распечатки.

## Данные профиля (payload)

Двоичная склейка, все длины — 4 байта, big-endian:

```
u32 длина .p12 | байты .p12 | u32 длина CA | байты CA | SHA-256 всего, что перед ним (32 байта)
```

- `.p12` — как есть, зашифрованный паролем. **Пароль в QR не кладётся**, пользователь вводит его в приложении.
- CA — PEM или DER, подходят оба.

## Разбиение на коды

1. Payload кодируется в Base64: стандартный алфавит RFC 4648, с `=` на конце, без переносов строк.
2. Строка Base64 режется на N подряд идущих кусков, не больше 99 штук. Рекомендуемый размер куска — до ~900 символов, тогда код остаётся читаемым с камеры.
3. Каждый QR содержит текст:

```
ECA1:<id>:<номер>/<N>:<кусок>
```

- `ECA1` — версия формата.
- `<id>` — 8 hex-символов, случайные и общие для всех кодов одного профиля. Коды с другим `id` приложение игнорирует.
- `<номер>` — с 1 по N.

Уровень коррекции ошибок рекомендуется M. Для печати на одном листе коды удобно раскладывать сеткой, по 6–8 штук на A4.

## Генерация

Готовый скрипт: `tools/qr/make_profile_qr.py`. Он собирает коды из своих `.p12` и CA, сам проверяет, что они склеиваются обратно, и сохраняет PNG по одному коду и лист со всеми.

```shell
pip install "qrcode[pil]"
python tools/qr/make_profile_qr.py client.p12 ca.pem --out qr-out
```

`--chunk` задаёт размер куска (по умолчанию 900), `--columns` — число кодов в ряду на листе (по умолчанию 3).
